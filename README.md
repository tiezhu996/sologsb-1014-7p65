# 格致 · 数学证明步骤编写与检查工具

一个完全在浏览器运行的数学证明工作台。使用步骤、引用和推理规则组织证明，实时检查结构与符号，并保留版本快照。

## 功能

- 逐步录入前提、推导和结论，选择推理规则并维护步骤引用。
- 检查未定义符号、缺失引用、循环引用和未证明目标。
- 为步骤记录旁注、反例和替代分支。
- 公式快捷输入、KaTeX 实时渲染、原生拖拽排序与键盘导航。
- 文档级撤销/重做，`localStorage` 自动保存，多版本文档管理。
- **两层持久化**：改动按步骤编号追加为编辑日志，停顿稳定后（或 `Ctrl+S`）合并成检查点；重开页面先读检查点再顺序重放日志，撤销/重做栈一并恢复。存储不足时按最早日志分批压缩；旧稿打开时自动迁移为初始检查点。
- 保存版本快照并进行逐步差异比较。
- 导出 Markdown 或 LaTeX 证明稿。

## 本地开发

```bash
npm install
npm run dev
```

浏览器打开终端输出的开发地址。数据保存在当前浏览器的 `localStorage` 中。

### 持久化模型（检查点 + 编辑日志）

数据分两个键保存，互不覆盖：

| 键 | 内容 |
| --- | --- |
| `sologsb-1014-checkpoint-v2` | 最近一次合并的完整检查点：全部文档、版本快照、截至该步的撤销/重做栈、当前步骤 |
| `sologsb-1014-editlog-v2` | 检查点之上按 `seq` 编号顺序追加的编辑日志（含普通编辑、撤销、重做） |

- 每次改动先追加一条日志（页面崩溃也只丢未落盘的最后一笔），停顿 1.5 秒或连续 12 步后合并成新检查点并清空日志区。
- 重开页面：先读检查点，再按编号顺序重放未合并日志重建文档与撤销/重做栈。
- 压缩写入若在两步之间崩溃导致编号缺口，重放会跳到缺口后第一条日志的 `before` 快照继续恢复——文档内容不丢，仅缺口前的撤销历史无法重建。
- 存储配额不足时把最早的日志按批折进检查点（当前文档与各文档内的版本快照始终完整）；仍不足才裁剪最旧的撤销栈层。
- 旧版整份保存的稿件（`sologsb-1014-proof-workspace-v1`，没有日志区）打开时自动迁移为初始检查点。

持久化逻辑的无浏览器验证：

```bash
node scripts/verify-persistence.mjs   # 检查点/日志/重放/压缩/迁移的 46 项断言
node scripts/verify-store.mjs         # 真实 ProofStore 的编辑-崩溃-重开集成验证
```

## 生产构建

```bash
npm run build
npm run preview
```

构建产物位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl/Cmd + Enter` | 添加推导步骤 |
| `Ctrl/Cmd + Shift + Enter` | 添加结论步骤 |
| `Alt + ↑ / ↓` | 切换当前步骤 |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |
| `Ctrl/Cmd + S` | 立即保存 |
| `Delete` | 删除当前步骤（编辑框外） |

## Docker

镜像内由 nginx 监听容器端口 `80`，不包含或硬编码宿主端口。

```bash
docker build -t math-proof-editor .
docker run --rm -p 10014:80 math-proof-editor
```

宿主端口 `10014` 仅用于本地运行示例，实际编排端口以根端口表为准。
